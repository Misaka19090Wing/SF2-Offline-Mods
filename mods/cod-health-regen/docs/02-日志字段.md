# 日志字段

单行 JSON，写入 `logs\health-regen-YYYYMMDD.jsonl`，同时尝试打到 stdout（双击启动时 stdout 不可用，写日志失败不影响运行）。

| `event` | 何时 | 字段 |
| --- | --- | --- |
| `ready` | worker 起来 | `version`, `pid`（可能是 0，尚未找到游戏）, `mode`(`run`/`dry`), `enabled`, `regen_delay_seconds`, `regen_per_second`, `tick_hz`, `bots` |
| `attached` | 连上客户端 | `pid`（**游戏** PID）, `exe`, `layout`, `dry` |
| `waiting-boot` | 客户端还没加载完，正在等（每分钟最多一条） | `pid`, `error` |
| `fields` | 反射解析成功 | `health`, `max`, `controller_pawn`, `controller_player`, `pawn_pri`, `pri_team`, `team_index`（`"0x.."`） |
| `pawn` | 发现/切换到本地玩家 pawn | `pawn`（`"0x.."`）, `via`（`level`/`level-no-name`/`objects`，哪条路先找到控制器；控制器先被认到、pawn 过一会儿才出现时可能是空串） |
| `pawn-lost` | 本地玩家 pawn 消失（死亡、换图） | `pawn` |
| `damage` | 血量比上一 tick 少（`log_damage` 打开时） | `health`, `max` |
| `death` | 血量 `<= 0`（每次死亡一条，不是每 tick） | `health` |
| `no-pawn` | 5 秒后仍没有可用 pawn，之后每 30 秒一条 | `seconds`, `world`, `level`, `actors`, `human_controllers`, `controller`, `pawn_pending`, `names`（当前名字表长度）, `via`, `sample_classes[]`（关卡前 8 个 actor 的类名）, `candidates[]`（每个 `*PlayerController` 的 `address/class/player/pawn/usable`） |
| `names` | 名字表被重读且长度变了（进图/换图） | `before`, `after` |
| `read-error` | 某次 tick 读内存失败（换图时常见） | `where`, `error`, `total` |
| `regen-bot` | 回血写到了某个队友（`bots` 打开时，每秒最多一条） | `bot`（`"0x.."`）, `health`, `max`（该队友的血上限）, `bots`（累计写入次数）, `dry` |
| `regen` | 真正写入了一次血量（**最多每秒一条**） | `health`（写入后的值）, `max` |
| `regen-would` | `dry_run` 下"本来会写成多少" | `health`, `target`, `max` |
| `full` | 血量到达上限 | `health`, `max` |
| `game-exit` | 游戏进程消失，worker 自行退出 | `pid` |
| `worker-error` | 单次 tick 抛了非 `OSError` 异常（会继续跑） | `where`, `error` |
| `fatal` | 无法继续（例如属性解析不到） | `error` |

判断"到底生效没有"：

1. `attached` + `fields` 有了 ⇒ 连上且偏移解析成功；
2. 进对局后出现 `pawn` ⇒ 认到了本地玩家；
3. 被打出 `damage`，4 秒后开始出 `regen`，最后 `full` ⇒ 回血在工作；
   - 只有 `no-pawn` 没有 `pawn` ⇒ 没认到玩家；`candidates` 会列出当时所有控制器，直接看 `player/pawn/usable` 就知道卡在哪一环；
4. 游戏关掉后 jsonl 末尾有 `game-exit` 且 `logs\worker.json` 不再更新 ⇒ worker 已自行退出。

`regen` 每秒最多一条是刻意的：10 Hz 全记会把日志刷爆，而"有没有在涨"看 `health` 就够了。
