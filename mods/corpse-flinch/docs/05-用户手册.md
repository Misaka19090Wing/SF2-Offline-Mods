## 1. 它能做什么

游戏里所有死亡单位都会变成布娃娃（ragdoll）。原版里，子弹打进尸体**只有血花和声音**，布娃娃完全不动——因为伤害链在"已经死了"之后就中断了。

这个补丁把**游戏自己算出的那一次命中**接回来，转成一个物理冲量施加到尸体上：

| 动作 | 效果 | 判据（游戏给的） |
| --- | --- | --- |
| 枪械命中尸体 | 中弹处受力，尸体晃/滑 | 武器的 `RifleHitResult`：命中 actor、命中点、法线、方向 |
| 箭 / 飞斧 / 投掷刀 / 手雷 | 命中当帧推一把 | 投射物的飞行折线与销毁时机 |
| 近战 F 挥击 | 推开准星前最近的尸体 | `DoingExigencyAttack` 状态位 |
| 投掷武器的左键近战 | 同上 | `BurstFireCount` 上升沿 + 弹药是否减少 |
| 按 E 抓住 / 再按 E 放开 | 尸体吊在准星前，跟着视角走 | `bPressingUsedKey`（跟着游戏的改键走） |

关键区别：**不是射线求交**。射线近似会把"打尸体旁边的墙"也判成命中（假阳性），又会把"擦着躯干边缘"判成没中（假阴性）。这里用的是游戏自己的结果，所以打墙、打地面、打空都不会动到旁边的尸体。

## 2. 环境要求

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10/11 x64 |
| 游戏 | SF2 离线客户端，且自带 `runtime\python\python.exe` 与 `runtime\tools\local_battle_bridge.py` |
| 对局 | 单人对局（打 AI 或打机器人）；联机服务器不在支持范围 |
| 权限 | 普通用户即可，**不需要管理员** |
| Python | **不需要另装**，用客户端自带的便携版 |
| 窗口 | 游戏必须在前台正常渲染（最小化时桥的命令会超时） |

怎么确认客户端带桥：

```
<游戏目录>\runtime\tools\local_battle_bridge.py     ← 有
<游戏目录>\runtime\python\python.exe               ← 有
```

两个都在就能装。少任何一个，先换一个完整客户端。

## 3. 安装

### 3.1 标准流程（推荐）

1. 把 `corpse-flinch-1.10.4.zip` **解压到游戏根目录**（有 `sf2.exe` 和 `运行游戏.cmd` 的那一层）
   - 不用手建 `mods` 文件夹：zip 里已经带 `mods\corpse-flinch\` 这一层，解压后就是 `<游戏>\mods\corpse-flinch\`
   - 解压到别处（比如别的盘、多出一层 `corpse-flinch-1.10.4\`）也能用：安装器会往上找游戏目录，找不到就弹框让你选
2. 双击 `<游戏>\mods\corpse-flinch\安装.cmd`
3. 看到自检结果（全绿或提示"游戏没开时正常"）即完成
4. 最后会问 **"现在就把鞭尸挂上吗？"** —— 直接回车即可；它会顺手启动游戏并挂上 worker，然后打印 `worker 已运行 PID xxxxx`
   - 不想现在启动就输入 `n`，之后自己双击启动器
5. 游戏根目录会多出一个 **`启动-鞭尸模式.cmd`**

安装器做的事（`tools\install.py`）：

- 先按 `logs\worker.pid` 停掉还在跑的旧 worker（否则旧代码/旧日志文件会被占着）
- 把整个包复制到 `<游戏>\mods\corpse-flinch\`（覆盖旧版本，跳过 `logs\`、`__pycache__`、`*.zip`、`*.pyc`）
- 逐项校验装完的文件（`corpse_flinch.py`、`config.json`、`sf2mod\`、`tools\` 都在），缺一个就报错退出，不假装成功
- 写一个纯 ASCII 的启动器 `<游戏>\启动-鞭尸模式.cmd`
- 跑一次只读自检 `tools\selftest.py`，把结果打出来
- 问你要不要立刻挂上 worker（`--no-start` 关掉）

安装器**不会**做的事：不改游戏文件、不写注册表、不装服务、不建开机启动项。

### 3.2 把补丁放在别处（不装进游戏目录）

直接把整个 `corpse-flinch\` 文件夹拖到 `安装.cmd` 上，或者命令行指定：

```
runtime\python\python.exe -X utf8 -B tools\install.py --game "E:\SF2-Offline-20261016"
```

`安装.cmd` 找不到游戏目录时也会弹框让你选（需要系统里有 `py`/`python`；纯客户端环境请用上面这条命令）。

### 3.3 校验文件完整性（可选）

```
runtime\python\python.exe -X utf8 -B tools\build_manifest.py --check
```

输出 `all good` 说明与 `MANIFEST.sha256` 一致；报"被改/缺失/多出"时，别用这份包，重新解压一次。

### 3.4 升级

重复 3.1 即可。`logs\` 与 `config.json` 会保留；如果你改过 `config.json`，新版新增的参数不会自动出现——对照 [§6](#6-参数详解) 手工补，或删掉 `config.json` 让它重建（会丢掉你的自定义）。

## 4. 启动与停止

### 4.1 一键启动（推荐）

双击 `<游戏>\启动-鞭尸模式.cmd`：

- **先确认游戏在跑**：没开就启动 `运行游戏.cmd`，最多等 15 秒看到游戏进程（1.10.2 及更早是先判断 worker，遗留的空转 worker 会让它直接退出、连游戏都不开——1.10.3 修掉了）
- 然后在后台用 `pythonw` 挂上 worker（无控制台窗口），日志照写
- worker 会等游戏最多 300 秒（`--wait 300`），所以"先开补丁、后进对局"也没问题
- 游戏刚启动时 worker 还挂不上（对象数组没建好、`PlayerController` 还没出现）：它会先写 `waiting-boot` 并**一直重试**（最多 1 小时，2→5 秒退避），加载完自动 `booted` → `ready`。这是 1.10.2 修掉的坑，旧版会直接 `fatal` 退出
- 已经在跑了？启动器看 `logs\worker.pid`：如果那个 worker 挂的是**当前**这个游戏进程，直接说"worker 已经在跑，不重复启动"然后退出；如果它挂的是上一个游戏进程（关游戏后遗留的），启动器会先停掉它再挂新的
- 起完等 2 秒检查；真起不来会弹窗，并把原因写进 `logs\launcher.log` 与 `logs\worker-console.log`
- 上一局如果崩了，屏幕上可能只剩一个 `Fatal error!` 框而进程还在跑。**1.10.4 起**启动器认出"游戏的所有可见窗口都只是这个 `Message` 框"，会把它清掉再启动新游戏（日志 `上一局崩溃了，只剩 Fatal error 窗口，先清掉它`），不用先去点"确定"；旧版会一直说"游戏已经在运行"然后什么都不做

启动器每一步都写进 `mods\corpse-flinch\logs\launcher.log`，双击没反应时先看它。

启动器只是"起游戏 + 起 worker"，不修改任何设置。

### 4.2 先开游戏，再手动挂

```
cd /d "<游戏>\mods\corpse-flinch"
..\..\runtime\python\python.exe -X utf8 -B corpse_flinch.py
```

带控制台运行时，日志会同时打到屏幕和文件，方便一边打一边看。

### 4.3 只看判定、不推尸体（调试）

```
..\..\runtime\python\python.exe -X utf8 -B corpse_flinch.py --dry
```

日志里依然有 `corpse-hit` / `melee-hit` / `projectile-hit` 与 `settled.moved`（dry 时为 0），但不会施加任何冲量。

### 4.4 确认挂上了

打开 `mods\corpse-flinch\logs\corpse-flinch-<日期>.jsonl`，找这样的三行：

```json
{"event": "attached", "pid": 59776, "functions": 27078, "properties": 92439}
{"event": "ready", "version": "1.10.4", "dry": false, "strength": 700.0, "max_impulse": 1800.0, "add_impulse": "0x2ebd0780", "melee": true, "projectile": true, "log": "...\corpse-flinch-20261018.jsonl"}
{"event": "world", "world": "0x51220380", "tracked": 17, "corpses": 15}
```

`world` 行里的 `corpses` 是当前地图上已经死掉的 pawn 数。它不是 0，说明已经能"看见"尸体了。

### 4.5 停止

- **1.10.3 起，关掉游戏 = worker 自己退出**：worker 每秒确认一次游戏进程还在（`GetExitCodeProcess`），没了就写 `{"event": "game-exit", "pid": 游戏 PID}` 然后结束，并删掉 `logs\worker.pid`。所以关游戏时不需要手动清理。
  - 旧版（1.10.2 及更早）不会：它会留在后台空转（`status` 的 `loop_ms` 掉到 0.0），直到 1 小时没有武器才 `idle-exit`；这种陈旧 worker 会占着 `worker.pid`，1.10.3 的启动器会自动把它换成新的。
- 想手动停 worker（比如它卡住了，按 pid 文件精确停）：
  ```
  $pid = Get-Content "<游戏>\mods\corpse-flinch\logs\worker.pid"; Stop-Process -Id $pid
  ```
- 或者按命令行匹配（不认 pid 文件时）：
  ```
  Get-CimInstance Win32_Process -Filter "Name='pythonw.exe'" | Where-Object CommandLine -like '*corpse_flinch.py*' | ForEach-Object { Stop-Process -Id $_.ProcessId }
  ```
  **不要**按 `pythonw.exe` 名字一把杀：客户端的启动器 `runtime\python\pythonw.exe` 也是这个名字，杀掉它等于关游戏。

## 5. 玩法

这一节说明每个动作"该怎么用"和"什么时候不会有反应"。

### 5.1 枪械

对着尸体开枪即可。着力点是**游戏命中表里的命中点**，方向也是命中表里的原始子弹方向（保留垂直分量，所以打脚会把它往前下方压、打胸口会往后带一点抬升；近战与投掷物才会压平到水平面 + 0.08 抬升）。

会有效：爆头、擦头、打手、打脚、打背面、远距离点射、霰弹命中。
不会有效：子弹穿过尸体后打到后面的墙（穿透出口点会被跳过，只算第一次命中）、打尸体旁边的任何东西。

### 5.2 弓 / 弩

判据和飞斧一样（投射物飞行折线），但**没有在真机验证过**：社区实测的日志里 18 次开火全是 `shot-miss`、`projectile-spawn` 为 0，说明箭要么不是 `SFCProjectile`/`SFProj_` 前缀的 actor，要么根本没被检测到（`sf2mod\game.py` 的 `PROJECTILE_PREFIXES`）。

所以弓现在算"**可能没反应**"：想试可以打一局，然后看日志里有没有 `projectile-spawn`；一个都没有就说明这条判据对箭不成立。有结果请把日志发出来。

### 5.3 飞斧 / 投掷刀 / 手雷

投掷物是**穿透**的：飞斧碰到尸体不会停下，会飞过去再落地。所以判据不是"碰撞事件"，而是"它飞过尸体的哪一段"：

- 命中时推一把，力量 `projectile_strength`（默认 1080，比子弹大）
- 判定半径 `projectile_radius`（默认 70 cm，按骨骼算，不是按身体中心）
- 还在你手里的那一个采样不算；起飞后 0.15 s 内只认正前方的尸体（防止站在尸体上投掷时把出生点当命中）

打空地、打墙、扔到很远的地方：日志里是 `projectile-miss`，不会误推。

### 5.4 近战（F 键）

挥击起手就判定，不用等动作播完。会对**准星前 `melee_reach`（默认 130 cm）内最近的尸体**施加冲量。

### 5.5 投掷武器的左键近战

手里拿着飞斧/投掷刀时左键是近战挥砍。这个动作没有专属状态位，所以补丁用"`BurstFireCount` 出现上升沿 + 0.3 秒后弹药没减少"来区分"挥砍"和"投掷"，一次挥击只推一次。

### 5.6 拖着尸体走（E 键）

1. 站在尸体 3 米（`drag_reach`）内，准星对着它，按一下 **E**
2. 尸体会被"抓住"，吊在准星前 `drag_distance`（默认 200 cm）；抬头它跟着抬，低头跟着落
3. 再按一下 **E** 放手

手感说明：

- 这是**冲量伺服**，不是硬约束。尸体会有一点滞后、会被墙挡住、会撞到别的东西，这都正常（GMod 的物理枪也是同一类做法）
- 抓的是**骨盆**（不是准星最近的那根骨头）：抓头/手会把尸体甩出去
- 拉太远会自动松手：超过 `drag_break`（默认 600 cm）并持续 0.3 秒
- 拖拽过程中尸体若被别的力打散，会重新找一根骨头继续抓（日志 `drag-rebone`）

按 E 没反应时看日志：`drag-none` 表示 3 米内没有可抓的尸体（会带 `near` 距离）；什么都没有表示按键没读到（聊天框聚焦时游戏会屏蔽交互键，这是正确行为）。

## 6. 参数详解

文件：`<游戏>\mods\corpse-flinch\config.json`。改完**重启补丁**才生效（游戏不用重开）。
JSON 严格：最后一项后面不能有逗号，`true/false` 不加引号，数字带小数点。

### 6.1 全局

| 键 | 默认 | 范围建议 | 说明 |
| --- | --- | --- | --- |
| `strength` | `700.0` | 300–1500 | 子弹冲量基准 |
| `max_impulse` | `1800.0` | 700–4000 | 任何单次冲量的上限（保险丝） |
| `settle_seconds` | `0.35` | 0.15–1.0 | 施加后等多久测位移（写进 `settled.moved`） |
| `poll_seconds` | `0.004` | 0.002–0.02 | 主循环间隔；调大省 CPU、响应变慢 |
| `wait_for_game` | `120.0` | 10–600 | 启动时等游戏出现的秒数（启动器会覆盖成 300） |
| `ai_priority` | `true` | `true`/`false` | R6 的人机 AI 用同一个原生入口：AI 局自动让出、结束自动收回 |
| `ai_priority_poll_seconds` | `1.0` | 0.2–5.0 | 多久重新检查一次当前是不是 AI 局 |
| `ai_priority_settle_seconds` | `2.0` | 0–10 | 离开 AI 局后等多久再把入口收回来（避免和 AI worker 抢） |
| `log_dir` | `"logs"` | — | 日志目录（相对包目录） |

### 6.2 近战

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `melee` | `true` | 总开关 |
| `melee_reach` | `130.0` | 判定半径（cm） |
| `melee_strength` | `700.0` | 冲量 |
| `swing_delay` | `0.30` | 挥击后等多久看弹药，用来区分投掷武器的左键挥砍 |

### 6.3 投射物

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `projectile` | `true` | 总开关 |
| `projectile_radius` | `70.0` | 命中判定半径（cm）。调小漏判变多，调大容易误推 |
| `projectile_grace` | `0.02` | 起手丢几个采样（秒），避免把出手点当命中 |
| `projectile_launch` | `0.15` | 这段时间内只认正前方（秒），防"站在尸体上投掷" |
| `projectile_lifetime` | `2.0` | 超过这个寿命才消失的投射物判为没命中（秒） |
| `projectile_strength` | `1080.0` | 冲量 |

### 6.4 拖拽

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `drag` | `true` | 总开关 |
| `drag_key` | `69` | 虚拟键码（69 = E）。改键后要同步这里 |
| `drag_reach` | `300.0` | 能抓住的距离（cm） |
| `drag_distance` | `200.0` | 尸体吊在准星前多远（cm） |
| `drag_lift` | `0.0` | 额外抬升（cm），觉得尸体贴地就加 10~20 |
| `drag_hz` | `60.0` | 伺服频率（Hz）。别超过 90，物理引擎积分不过来会抖 |
| `drag_kp` | `20.0` | 刚度：越大越"硬"，太大就抖 |
| `drag_kd` | `9.0` | 阻尼：临界阻尼约等于 `2*sqrt(kp)` |
| `drag_max_speed` | `700.0` | 速度上限（cm/s） |
| `drag_max_accel` | `2500.0` | 加速度上限（cm/s²） |
| `drag_mass` | `20.0` | 初始质量估计（kg），会在线学习 |
| `drag_impulse` | `900.0` | 单次冲量上限 |
| `drag_gravity` | `1.0` | 重力补偿系数；1.0 = 抵消重力让它悬停 |
| `drag_break` | `600.0` | 超过这个距离自动松手（cm） |

## 7. 命令行参数

```
runtime\python\python.exe -X utf8 -B corpse_flinch.py [选项]
```

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `--version` | — | 打印 `corpse-flinch 1.10.4` 后退出 |
| `--config PATH` | `config.json` | 用另一份配置 |
| `--pid N` | 自动 | 指定客户端 PID（多开时有用） |
| `--strength X` | 700 | 覆盖 `strength` |
| `--max-impulse X` | 1800 | 覆盖 `max_impulse` |
| `--wait S` | 120 | 等游戏出现的秒数；启动器用 300 |
| `--seconds S` | 0 | 跑多少秒后退出，0 = 直到游戏退出 |
| `--log-dir DIR` | `logs` | 日志目录 |
| `--dry` | 关 | 只记录、不施加冲量 |

## 8. 日志怎么读

位置：`<游戏>\mods\corpse-flinch\logs\corpse-flinch-YYYYMMDD.jsonl`（每行一个 JSON），控制台版另有 `worker-console.log`。字段全表见 [`06-日志字段.md`](06-日志字段.md)。

### 8.1 三条判决行

```json

{"event": "corpse-hit", "shots": 13, "ammo": 4, "rounds": 1, "corpses": ["SFCPawnAI_Soldier_95"], "impacts": [{"list": "impact", "actor": "SFCPawnAI_Soldier_95", "loc": [-4834.3, -5294.7, 11365.9], "dir": [0.58, 0.81, -0.07]}], "applied": [{"corpse": "SFCPawnAI_Soldier_95", "corpse_mesh": "0x5a1c3400", "hit": [-4834.3, -5294.7, 11365.9], "dir": [0.58, 0.81, -0.07], "impulse": [406.0, 567.0, -49.0], "strength": 700.0}]}
```

- 代码里**没有单独的 `shot` 事件**：一次开火落地时一定被写成 `shot-miss`（没打到尸体）或 `corpse-hit`（打到了）之一
- `corpse-hit`：至少一发打中尸体，`corpses` 是**被打中的尸体名列表**，`applied` 列出每个受影响的尸体
- `settled`：`settle_seconds` 之后尸体实际移动了 `moved` 厘米——**这是唯一能证明"真的推动了"的数字**

### 8.2 自证三件事

| 你想确认 | 看哪几行 | 判据 |
| --- | --- | --- |
| 打中的是尸体而不是墙 | `corpse-hit` 的 `corpses[]` / `impacts[].actor` | `corpses` 非空才是尸体；打墙只有 `shot-miss`；有 `corpse-hit` 才会有 `settled` |
| 推的力气对不对 | `settled.moved` | 子弹 5~40 cm、投掷 20~60 cm 属正常；0.0 表示没推动（卡在几何里或 dry） |
| 投掷是"命中"还是"擦过" | `projectile-hit` 的 `distance` / `age` / `path` | `distance` 越小越实；`age` 是飞行时长；`path` 是采样点数 |

### 8.3 常见组合对照

| 日志 | 含义 | 下一步 |
| --- | --- | --- |
| 只有 `shot-miss`，`impacts` 里是墙/地面 | 这一枪没打中尸体 | 不用管 |
| `shot-miss impacts="no-bullet-trace"` | 手里不是枪（拿着飞斧/刀/手雷时命中表是无关内存） | 正常 |
| `corpse-hit-dry` | 打中了尸体但 `--dry` 或没有可施加的骨骼 | 检查是否 dry |
| `projectile-miss` | 投射物飞完/消失，但没进判定半径 | 距离差一点就调大 `projectile_radius` |
| `drag-none` | 按了 E 但 3 米内没抓到尸体 | 靠近点，或调大 `drag_reach` |
| `worker-error` | 某个模块抛异常，已兜底继续跑 | 看 `where` 与 `error`，见 [`04-排错.md`](04-排错.md) §2 |

## 9. 调参手册

### 9.1 推得太轻 / 太重

- 太轻：`strength` 700 → 900；还轻就 1200
- 太重（尸体飞出很远、甚至穿墙）：`strength` 降到 400~500，同时把 `max_impulse` 降到 1200
- 想要"每一枪都明显动一下"：`strength` 500 + `settle_seconds` 0.5（观感更清楚）

### 9.2 投掷有延迟 / 投不中

- 延迟：`projectile_grace` 已经是 0.02（只丢一个采样）；若还有明显延迟，检查 `poll_seconds` 是否被调大
- 投不中但明明打到了：`projectile_radius` 70 → 90（代价是擦过也可能算中）
- 投到墙上却推了尸体：`projectile_radius` 降到 55~60

### 9.3 拖拽手感

| 症状 | 改法 |
| --- | --- |
| 抖 / 鬼畜 | `drag_hz` 降到 50；`drag_kp` 降到 12；`drag_kd` 保持 ≈ `2*sqrt(kp)` |
| 跟不上手、软绵绵 | `drag_kp` 升到 30；`drag_max_speed` 升到 900 |
| 尸体被甩飞 | `drag_max_accel` 降到 1500；`drag_impulse` 降到 600 |
| 尸体老是沉到地面 | `drag_lift` 加 10~20；`drag_gravity` 保持 1.0 |
| 想抓得更远 | `drag_reach` 300 → 400；`drag_break` 同步加 |

### 9.4 拖拽时把尸体拽出地图

`drag_break` 600 → 400，并把 `drag_max_speed` 降到 500。尸体掉出地图会在几秒后被游戏回收，日志里会出现 `drag-end reason="gone"`。

## 10. 卸载与还原

- 双击 `<游戏>\mods\corpse-flinch\卸载.cmd`（它会先按 `logs\worker.pid` 停掉 worker，再删包目录与启动器）
- 删不掉先关 Obsidian/编辑器：`docs\` 常被 Obsidian 当 vault 打开，会报 `The process cannot access the file`。关掉后再在卸载窗口按**回车**重试（输入 `n` 放弃）
- 或手动删：`<游戏>\mods\corpse-flinch\` 与 `<游戏>\启动-鞭尸模式.cmd`
- 游戏本体的任何文件都没有被改过，删掉即完全还原
- 想保留日志：先把 `mods\corpse-flinch\logs\` 拷出来

## 11. FAQ

**Q：会不会被反作弊/BE 判定为作弊？**
A：补丁只在本地进程内存里读写，不注入 DLL、不改游戏文件、不联网。但它确实改了游戏行为，联机服务器上使用可能违反服务器规则——所以只支持单人对局。

**Q：需要管理员权限吗？**
A：不需要。安装/卸载都是普通文件复制。

**Q：能和朋友一起用吗？**
A：单人各自用没问题。多人联机不在支持范围（判据只认本地玩家自己的命中）。

**Q：为什么打活人没反应？**
A：设计如此。只对 `Health <= 0` 的 pawn 施加冲量，避免影响战斗平衡与 AI。

**Q：游戏更新后失效了怎么办？**
A：现象是 `attached` 之后没有 `world`，或 `world` 里 `corpses` 永远是 0，或打尸体只出现 `shot-miss` 从不出现 `corpse-hit`。按 [`02-数据结构与偏移.md`](02-数据结构与偏移.md) §7 重新测量偏移；`tools\selftest.py` 会先告诉你哪一项对不上。

**Q：CPU 占用高吗？**
A：主循环 4 ms 一次，只遍历当前地图的 actor 表（不扫描全局对象表）。日志里的 `status.loop_ms` 正常在 1~3 ms。

**Q：日志会长多大？**
A：一场几十分钟的对局通常几百 KB。可以随时删；补丁每天一个新文件。

**Q：能只开拖拽、不开鞭尸吗？**
A：可以。`config.json` 里把 `melee`、`projectile` 设为 `false`，`drag` 保持 `true`。

**Q：装完双击启动器，什么都没发生？**
A：先看 `mods\corpse-flinch\logs\launcher.log`（启动器每一步都记在这里）。三种常见情况：

1. 里面只有 `worker 启动后立刻退出了（exit xxx）` → 再看 `logs\worker-console.log` 和 `logs\crash.log`，那里有 Python 的报错原文
2. 根本没有 `launcher.log` → 启动器没跑起来（多半还指向旧路径）。重跑一次 `安装.cmd` 让它重写启动器
3. 提示"worker 已经在跑"但游戏里没反应 → 1.10.3 会自动换掉"挂着上一个游戏进程"的 worker；若仍不行（比如它卡住了），按 §4.5 手动停掉，再双击启动器

**Q：卸载报"文件被占用"，删不掉怎么办？**
A：多半是 Obsidian / 编辑器 / 资源管理器正开着 `mods\corpse-flinch\docs` 里的文件（Obsidian 会把整个 `docs` 当 vault 打开）。先关掉它们，再回到卸载窗口按**回车**重试（卸载器会问"关掉打开它的程序后按回车重试，输入 n 放弃"）；也可以关掉后再双击一次 `卸载.cmd`。卸载器会先停 worker，再重试 20 次删除。

## 12. 已知限制

1. **只对本地玩家自己的命中生效**：读的是你手上武器的命中记录、你自己发射的投射物、你自己的挥击。AI 打尸体不会有反应。
2. **投掷物是穿透的**：命中不会让它停下，所以判定靠"飞行折线 + 销毁时机"，不是碰撞事件。极端情况（尸体紧贴墙、投掷物贴地飞行）可能漏判。
3. **拖拽是冲量伺服，不是硬约束**：尸体有延迟、会被墙挡住、会撞翻别的东西；抓太重的尸体会明显迟钝（质量在线学习，前一两秒是估计值）。
4. **需要前台渲染**：游戏最小化时桥的命令无法完成，补丁会超时并重试。
5. **偏移与游戏版本绑定**：换客户端版本可能需要重测（`docs\02` §7）。
6. **面部表情不在本版本范围内**：本包不含任何面部/morph 相关功能。
