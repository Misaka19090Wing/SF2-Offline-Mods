# 06 · 日志字段

所有判定都写成**单行 JSON**（JSONL），一行一个事件。这份文档是字段字典，也是"怎么用日志证明补丁真的在工作"的操作手册。

- 位置：`<游戏>\mods\corpse-flinch\logs\corpse-flinch-YYYYMMDD.jsonl`（每天一个文件，UTF-8）
- 同目录下还有几份**不是 JSON** 的排错文件，别拿 `ConvertFrom-Json` 去解：
  - `launcher.log`：启动器每一步（起游戏、判重、起 worker、失败原因），一行一条
  - `worker-console.log`：worker 的 stdout/stderr 原文；有控制台手动跑时是空的，双击启动时才有内容
  - `crash.log`：worker 最外层异常兜底写的 traceback；**正常不存在**，出现就说明 worker 崩过
  - `worker.pid`：当前 worker 的 PID（判重、停止、卸载都读它；`ready.pid` 是**游戏** PID）
- 控制台模式（`--dry` 或手动跑）会同时打到屏幕上
- 无控制台（启动器用 `pythonw`）时，stdout/stderr 落到 `logs\worker-console.log`
- 字段名全小写；坐标与距离单位是**厘米**；地址一律 `"0x..."` 字符串
- 事件名是 kebab-case；未知事件不影响解析（新版本可能加字段）

## 1. 生命周期

| 事件 | 字段 | 含义 |
| --- | --- | --- |
| `process` | `pid` | 找到了游戏进程，开始连接。`pid` 是**游戏进程**（不是 worker 自己） |
| `waiting-boot` | `attempt`、`error`、`waited`、`retry_in` | 游戏还没加载完，挂不上，正在等（1.10.2+）。同一错误每分钟只记一行；见到它说明 worker **活着**，不是崩了 |
| `booted` | `attempts`、`waited` | 等到了：第 N 次尝试挂上了，`waited` 是总共等了多少秒 |
| `boot-timeout` | `attempts`、`error` | 等满 1 小时仍挂不上，放弃退出（游戏没起来 / 卡在启动器） |
| `bridge` | `status`、`seconds` | 等游戏主线程推进时的心跳：`{"status": "waiting", "seconds": 15.0}`，每 15 秒一条 |
| `attached` | `pid`、`functions`、`properties` | 桥装好、函数/属性表已加载。`pid` 是**游戏进程** |
| `attach` | `message` | 挂接过程中的提示（等待、重试） |
| `ready` | `version`、`pid`、`dry`、`strength`、`max_impulse`、`add_impulse`、`melee`、`projectile`、`log` | 进入主循环。`add_impulse` 是函数地址，`log` 是日志路径 |
| `world` | `world`、`tracked`、`corpses` | 检测到对局/换图。`tracked` 是跟踪的 pawn 数，`corpses` 是其中已死亡数 |
| `weapon` | `weapon`、`name` | 玩家手上的武器变了 |
| `status` | `tracked`、`corpses`、`shots`、`hits`、`melee`、`projectiles`、`ammo`、`drag`、`loop_ms` | 每 20 秒一次的心跳与计数 |
| `stopped` | 各计数器、`log` | 正常退出前的汇总 |
| `game-exit` | `pid` | 游戏进程没了（你关了游戏），worker 跟着退出（1.10.3+）。`pid` 是**游戏进程**。旧版没有这条，会继续空转到 `idle-exit` |
| `idle-exit` | — | 长时间没有武器/对局，自动退出（1 小时无武器） |
| `fatal` | `reason` | 启动阶段失败（找不到游戏、桥装不上等） |
| `worker-error` | `where`、`error` | 某个模块抛异常，已兜底**继续跑** |

## 2. 枪械

一次开火只会产生两种事件：`shot-miss`（没打中尸体）或 `corpse-hit`（打中了）。代码里没有单独写出的 `shot` 事件——它是中间状态，落地前已经被改写成上面两者之一。

```json
{"event": "shot-miss", "shots": 13, "ammo": 29, "rounds": 1, "impacts": "no-bullet-trace"}
{"event": "shot-miss", "shots": 14, "ammo": 28, "rounds": 1,
 "impacts": [{"list": "impact", "index": 0, "actor": "StaticMeshCollectionActor_1114",
              "loc": [1581.9, -1471.9, 397.6], "dir": [0.28, 0.9, 0.34]}]}
{"event": "corpse-hit", "shots": 15, "ammo": 4, "rounds": 1,
 "impacts": [{"list": "impact", "index": 0, "actor": "SFCPawnAI_Soldier_95",
              "loc": [-645.3, -1041.2, 81.6], "dir": [0.58, 0.81, -0.07]},
             {"list": "impact", "index": 1, "actor": "StaticMeshCollectionActor_1109", "loc": [], "dir": []},
             {"list": "penetration", "index": 0, "actor": "SFCPawnAI_Soldier_95", "loc": [], "dir": []}],
 "corpses": ["SFCPawnAI_Soldier_95"],
 "applied": [{"corpse": "SFCPawnAI_Soldier_95", "corpse_mesh": "0xb8c4f600",
              "hit": [-645.3, -1041.2, 81.6], "dir": [0.58, 0.81, -0.07],
              "impulse": [405.5, 568.7, -46.4], "strength": 700.0}]}
{"event": "settled", "moved": 15.16, "strength": 700.0,
 "from": [-4830.2, -5300.1, 11360.0], "to": [-4815.4, -5296.2, 11360.4]}
```

| 事件 | 字段 | 含义 |
| --- | --- | --- |
| `shot-miss` | `impacts: "no-bullet-trace"` | 手里不是子弹类武器，命中表是无关内存（**正常现象**） |
| `shot-miss` | `impacts: [ … ]` | 打中了东西，但**都不是尸体**（打墙、地面、活人） |
| `corpse-hit` | `impacts[]`、`corpses[]`、`applied[]` | 至少一发打中尸体；`corpses` 是被打中的尸体名列表 |
| `corpse-hit-dry` | 同上，`applied[].dry: true` | `--dry` 模式下"本应命中" |
| `shot-failed` | `error` | 读命中表时抛异常（只记一次，不刷屏） |
| `settled` | `moved` 实际位移（cm）、`strength` 施加量、`from`/`to` 质心坐标 | 施加后 `settle_seconds` 的测量 |

`impacts[]` 每一项是游戏命中表里的原始条目：

| 字段 | 含义 |
| --- | --- |
| `list` | `impact` = 入口点（会施加冲量）；`penetration` = 出口点（**跳过**，否则一枪算两次） |
| `index` | 该表内的序号 |
| `actor` | 被命中的 actor 名 |
| `loc` | 命中点世界坐标（`penetration` 条目是出口点） |
| `dir` | 该点的方向（单位向量，**保留垂直分量**） |

`applied[]` 每一项：

| 字段 | 含义 |
| --- | --- |
| `corpse` | 尸体 actor 名（如 `SFCPawn_12`） |
| `corpse_mesh` | 骨骼网格组件地址 |
| `hit` | 着力点（世界的命中点） |
| `dir` | 单位方向（水平投影 + 0.08 抬升） |
| `impulse` | 实际冲量向量 |
| `strength` | 标量大小（已按 `max_impulse` 截断） |
| `dry` | 只在 dry 模式出现，`true` |
| `error` | 施加失败时的异常文本（此时没有 `impulse`） |

## 3. 近战

```json
{"event": "swing", "source": "exigency", "n": 3}
{"event": "melee-hit", "source": "burst", "corpse": "SFCPawn_8", "bone": 62, "distance": 61.6,
 "applied": {"corpse_mesh": "0x5a1c3400", "hit": [-4834.3, -5294.7, 11365.9], "dir": [0.7, 0.71, 0.08],
             "impulse": [496.2, 503.3, 56.0], "strength": 700.0}}
{"event": "melee-miss", "source": "exigency", "near": 212.4}
```

| 事件 | 字段 | 含义 |
| --- | --- | --- |
| `swing` | `source`（`exigency` = F 键状态位，`burst` = 投掷武器左键）、`n` 第几次 | 检测到挥击起手 |
| `melee-hit` | `corpse`、`bone` 骨骼序号、`distance` 该骨骼到玩家的距离（cm）、`applied` | 命中并施加 |
| `melee-miss` | `near` 最近尸体骨骼的距离（cm，无则 `null`） | 半径内没有尸体 |

## 4. 投射物（弓 / 飞斧 / 投掷刀 / 手雷）

```json
{"event": "projectile-spawn", "klass": "SFCProjectileTomahawk", "address": "0x66bf0f00"}
{"event": "projectile-hit", "corpse": "SFCPawn_3", "bone": 11, "distance": 8.0,
 "klass": "SFCProjectileTomahawk", "age": 0.84, "path": 49,
 "applied": {"corpse_mesh": "0x5a1c3400", "hit": [-4900.0, -5280.0, 11370.0], "dir": [0.62, 0.78, 0.08],
             "impulse": [766.0, 963.6, 98.8], "strength": 1080.0}}
{"event": "projectile-miss", "klass": "SFProj_Arrow", "age": 1.31, "near": 142.7}
{"event": "projectile-lost", "klass": "SFProj_Arrow", "age": 2.05, "points": 61, "why": "released"}
```

| 事件 | 字段 | 含义 |
| --- | --- | --- |
| `projectile-spawn` | `klass`、`address` | 发现新的投射物 |
| `projectile-hit` | `corpse`、`bone`、`distance` 最近骨骼距离（cm）、`age` 飞行秒数、`path` 采样点数、`applied` | 命中，冲量已施加 |
| `projectile-miss` | `age`、`near` | 整个飞行里都没进半径；`near` 是历史最近距离 |
| `projectile-lost` | `points`、`why`（`released` = 对象被回收） | 没等到判定就丢失（打空、飞出地图） |

判据说明：投掷物是穿透的，所以"碰到"不会产生事件。这里的命中 = 折线上某一段与尸体骨骼的距离 < `projectile_radius`；`distance` 越小越"实"。

## 5. 拖拽（E 键）

```json
{"event": "drag-start", "source": "game", "key": 1, "keys_word": "0x40", "corpse": "SFCPawn_9",
 "gap": 34.7, "held_at": [-4870.0, -5285.0, 11360.0], "bone": 0, "bone_name": "Bip01-Pelvis",
 "mass": 20.0, "lift": 0.0}
{"event": "drag-none", "source": "game", "key": 2, "keys_word": "0x40", "near": 412.0, "reach": 300.0}
{"event": "drag-rebone", "bone": 74, "bone_name": "Bip01-L-Toe0", "to": "root", "why": "bone did not move", "cm": 0.12}
{"event": "drag-end", "reason": "toggled", "seconds": 6.42, "moved": 537.5, "path": 1819.1,
 "ticks": 385, "calls": 385, "mass": 7.5, "error": 18.2, "bone": 0, "bone_name": "Bip01-Pelvis"}
```

| 事件 | 字段 | 含义 |
| --- | --- | --- |
| `drag-start` | `source`（`game` 读游戏状态位 / `os` 退回 `GetAsyncKeyState`）、`key` 按键计数、`keys_word` 原始状态字（hex）、`corpse`、`gap` 准星骨骼与抓取点的距离、`held_at` 抓取时的尸体位置、`bone`/`bone_name` 实际抓的骨（骨盆）、`mass` 初始估算、`lift` | 抓住 |
| `drag-none` | `near` 最近尸体骨骼距离、`reach` 阈值 | 按了 E 但没抓到 |
| `drag-rebone` | `bone`、`bone_name`、`to`、`why`、`cm` | 抓的骨头没物理体（脚趾等），改用根骨骼 |
| `drag-end` | `reason`（`toggled` 再按一次 / `too-far` 超距 / `gone` 尸体消失 / `world` 换图 / `no-player`）、`seconds` 持续时间、`moved` 尸体总位移、`path` 累计路径长度、`ticks` 控制次数、`calls` 桥调用次数、`mass` 学习后的质量、`error` 结束时的跟踪误差、`bone`/`bone_name` | 松手 |

`moved` 与 `path` 的关系能看出手感：`moved ≈ path` 说明拖得顺；`path` 远大于 `moved` 说明尸体系在撞墙/打转。

## 6. 用日志回答具体问题

### 6.1 "这一枪到底算不算打中尸体？"

```powershell
Get-Content mods\corpse-flinch\logs\corpse-flinch-20261018.jsonl |
  ConvertFrom-Json | Where-Object { $_.event -in @('shot-miss','corpse-hit','settled') } |
  Select-Object event, shots, corpses, moved, strength | Format-Table
```

同一次开火只会留下 `shot-miss`（没打中尸体）**或** `corpse-hit`（打中了）；看到 `corpse-hit` 且 `corpses` 里有名字，就是真的打中了。

### 6.2 "为什么推不动？"

```powershell
Get-Content ... | ConvertFrom-Json | Where-Object { $_.event -eq 'settled' -and $_.moved -lt 1.0 }
```

`moved < 1.0` 的三种原因：尸体卡在几何里（贴墙/贴地）、`strength` 太小、`--dry`（此时事件名是 `corpse-hit-dry`）。

### 6.3 "投掷为什么没反应？"

```powershell
Get-Content ... | ConvertFrom-Json | Where-Object { $_.event -like 'projectile-*' } |
  Select-Object event, klass, age, near, distance, path | Format-Table
```

- 只有 `projectile-spawn` + `projectile-lost`：飞出去了，从没靠近任何尸体
- `projectile-miss` 且 `near` 在 70~120：差一点，`projectile_radius` 调大一点
- 连 `projectile-spawn` 都没有：这个投射物类没被识别，看 [`04-排错.md`](04-排错.md) §2

### 6.4 "补丁有没有在拖慢游戏？"

```powershell
Get-Content ... | ConvertFrom-Json | Where-Object { $_.event -eq 'status' } |
  Select-Object tracked, corpses, loop_ms
```

`loop_ms` 正常 1~3；持续 > 10 说明 `poll_seconds` 太小或尸体太多。

### 6.5 "双击启动器没反应，先看哪份日志？"

```powershell
$logs = "E:\SF2-Offline-20261016\mods\corpse-flinch\logs"
Get-Content "$logs\launcher.log" -Tail 30          # 启动器走到哪一步
Get-Content "$logs\worker-console.log" -Tail 40    # worker 自己的报错
Test-Path "$logs\crash.log"; Get-Content "$logs\crash.log" -Tail 40
Get-Content "$logs\worker.pid"                     # 当前 worker 的 PID
```

判定顺序：`launcher.log` 里没有 `挂 worker` ⇒ 启动器没走到那一步（看它上面的行）；有 `worker 启动后立刻退出了（exit …）` ⇒ 接着看 `worker-console.log` / `crash.log`；有 `worker 已启动 pid=` 且该 pid 还在 ⇒ worker 活着，问题在判定侧（回到 §6.1）。

再看 jsonl 的第一批事件：出现 `waiting-boot` 说明游戏还没加载完、worker 在等（正常，1.10.2+）；出现 `fatal` 才是真挂了——`reason` 里若是 `Unexpected object array` 或 `Battle API incomplete`，那是 1.10.1 及更早的挂载竞态，换 1.10.2。

## 7. 字段速查

| 字段 | 出现于 | 类型 | 说明 |
| --- | --- | --- | --- |
| `event` | 全部 | string | 事件名 |
| `pid` | `process` / `attached` / `ready` | int | `process` 是自己的，其余是游戏进程 |
| `dry` | `ready` / `applied[]` | bool | 是否只判定不施加 |
| `strength` / `max_impulse` | `ready` / `applied[]` / `settled` | float | 冲量基准与上限 |
| `world` | `world` | string | 世界对象地址（换图会变） |
| `tracked` / `corpses` | `world` / `status` | int | 跟踪的 pawn 数 / 其中尸体数 |
| `corpses` | `corpse-hit` | string[] | **被打中的尸体名列表**（与上面的计数同名但类型不同，注意区分） |
| `shots` / `ammo` / `rounds` / `impacts` | 枪械事件 | int / list | 计数与命中表（`impacts` 为数组，`"no-bullet-trace"` 表示手里不是子弹类武器） |
| `applied` | 命中事件 | object 或 array | 施加记录（见 §2） |
| `corpse` / `corpse_mesh` | 命中 / 拖拽 | string | actor 名 / 网格组件地址 |
| `bone` / `bone_name` | 近战 / 投射物 / 拖拽 | int / string | 骨骼序号与名字 |
| `distance` / `near` / `gap` | 命中 / 拖拽 | float | 距离（cm） |
| `impulse` / `dir` / `hit` | `applied` | float[3] | 冲量、单位方向、着力点 |
| `moved` / `path` | `settled` / `drag-end` | float | 位移 / 累计路径（cm） |
| `age` / `path`(投射物) | 投射物 | float / int | 飞行秒数 / 采样点数 |
| `reason` / `why` | `drag-end` / `projectile-lost` | string | 结束原因 |
| `error` | `worker-error` / `applied` / `drag-end` | string | 异常文本或跟踪误差 |
| `loop_ms` | `status` | float | 一轮主循环耗时 |

## R6 人机 AI 让位（1.11.0）

R6 版本的人机 AI 用同一个 `0x6008D0` 入口（批量协议），所以 AI 局里本 mod 会让出入口。

| 事件 | 何时 | 字段 |
| --- | --- | --- |
| `ai-priority` | 让出 / 收回入口 | `state`（`released`/`owned`）, `reason`（`objective:sfblastinggame_…` / `hero:…` / `route:<map>` / `free-play` / `no-ai-worker`）, `note` |
| `bridge-foreign` | 入口被别的桥占着、拿不回来（每分钟最多一条） | `note` 或 `error` |
| `bridge-release-failed` | 让出时 `restore()` 失败 | `error` |

另外 `corpse-hit` / `applied` 记录里可能出现 `"skipped": "ai-priority"` —— 表示这一下因为 AI 局在跑而被**故意跳过**，不是没打中。
