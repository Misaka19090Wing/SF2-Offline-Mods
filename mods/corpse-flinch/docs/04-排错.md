# 04 · 排错

先跑只读自检，它会把每一步的结果打印出来：

```bat
<游戏>\runtime\python\python.exe -X utf8 -B <游戏>\mods\corpse-flinch\tools\selftest.py
```

## 0. 安装与启动阶段

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `安装.cmd` 提示 `Could not find a Python to run tools\install.py.` | 没找到内置 runtime python，系统里也没有 `py`/`python`，而且没把游戏目录拖给它 | 把游戏目录拖到 `安装.cmd` 上（它用 `<游戏>\runtime\python\python.exe`）；客户端自带 python，正常不会出现 |
| `安装.cmd` 弹出"选择游戏目录"对话框 | 自动查找没命中（补丁被解压到游戏目录之外，且没有内置 python 可用来跑安装器） | 选包含 `runtime` 与 `test-client` 的那个文件夹；或手动 `runtime\python\python.exe -X utf8 -B tools\install.py --game <游戏目录>` |
| `安装.cmd` 一闪而过 | 双击时全屏/窗口切换让窗口丢焦点 | 在本文件夹空白处 shift+右键 → "在此处打开 PowerShell"，输入 `.\安装.cmd` 看完整输出 |
| `[错误] 装完缺文件，安装没有成功：` | 复制没完成（杀毒拦截 / 磁盘满 / 文件被占用） | 按它列出的缺失路径排查；关掉占用程序或杀软实时扫描后重跑 `安装.cmd`，仍失败就重新解压一份 |
| 自检里 `运行库导入失败：No module named 'local_route_bridge'` | 游戏目录不是本补丁对应的那一版（缺少 `runtime\tools\` 或 `runtime\python-deps`） | 确认游戏目录指对了；本补丁只适配 SF2 离线客户端（见 `docs/02` 的版本校验） |
| 自检里 `[FAIL] PlayerController 0x0` | 游戏停在大厅，没有进入对局 | 本项在那时必然失败，正常；进一局再跑 |
| 双击 `启动-鞭尸模式.cmd` 什么都没发生 | 先看 `mods\corpse-flinch\logs\launcher.log` | 1.10.1 起启动器每步都写这份日志。没有这个文件 ⇒ 启动器还是旧版，重跑 `安装.cmd` 重写它 |
| 日志写 `游戏已经在运行 pid=xxxxx`，但屏幕上没有游戏，只有一个 `Fatal error!`/`Message` 框 | 上一局崩溃留下的残留进程：主窗口早关了，只剩引擎的崩溃提示框 | 1.10.4 起启动器认出"所有可见窗口标题都是 `Message`"就清掉它重开；旧版得先手动点掉那个框。崩溃原因看 `runtime\test-client\SFGame\Logs\UE3AutoReportDump*.txt`（`GameViewport == NULL`、`D3D9Device.cpp D3DERR_INVALIDCALL` 等，都是客户端自己崩） |
| 弹窗 `worker 启动后立刻退出了（exit 120）` | `logs\worker-console.log` | 1.10.0 及更早的致命 bug：两层 pythonw 继承失效的 std 句柄，worker 第一行 `print` 就抛 `OSError: [Errno 22] Invalid argument`。用 1.10.1+ |
| 弹窗 `worker 启动后立刻退出了（exit 1）` | `logs\crash.log` | worker 自己崩了，`crash.log` 里有完整 traceback |
| 提示 `worker 已经在跑，不重复启动 pid=xxxxx`，但游戏里没反应 | `logs\worker.pid` 与任务管理器 | 1.10.3 会核对这个 worker 挂的是不是**当前**游戏进程，不是就停掉重挂。若它卡住了，按 §4 手动停掉再双击启动器 |
| 启动器说游戏在运行，但 worker 没起来 | `logs\launcher.log` 里 `挂 worker` 之后的行 | 多半被安全软件拦了（pythonw 首次运行会弹询问），放行后重试 |
| `logs` 是个文件而不是目录 | 资源管理器看 `mods\corpse-flinch\logs` | worker 启动即死（`FileExistsError: [WinError 183]`）。删掉这个文件后重装 |
| 双击启动器后 jsonl 里只有 `{"event": "fatal", "reason": "ValueError: Unexpected object array"}` | worker 在游戏还没加载完时就 attach（1.10.0/1.10.1 的竞态） | 用 **1.10.2+**：它会打 `waiting-boot` 并一直等游戏加载好 |
| 同上，但 reason 是 `RuntimeError: Battle API incomplete: N functions, 0 controllers` | 桥的 trampoline 要等 `PlayerController` 出现才能装 | 同上。1.10.2 会等到大厅/对局加载完 |
| `{"event": "boot-timeout", ...}` | 等了一小时游戏还没加载完（或游戏根本没起来） | 确认游戏窗口真的开着且没卡在启动器；重启游戏与 worker |
| 卡在 `waiting-boot` 几分钟 | 游戏在加载/停在启动器界面 | 正常，同一错误每分钟只记一行；进到大厅后应出现 `booted` → `ready` |
| `卸载.cmd` 报 `The process cannot access the file` | 有程序开着包内文件：Obsidian 把 `docs\` 当 vault 打开、编辑器/资源管理器窗口、杀毒扫描 | 关掉它们，回到卸载窗口按**回车**重试（不关就输入 `n` 放弃；卸载器会先按 `logs\worker.pid` 停 worker，再重试 20 次） |

## 1. 挂接阶段

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `没找到游戏目录。请选择包含 runtime 和 test-client 的那个文件夹。` | 文件夹被解压到了别处，自动查找没命中 | 搬到 `<游戏>\mods\`，或用 `--game <游戏目录>` 指定 |
| `游戏没有运行：先启动游戏...` | 补丁先于游戏启动 | 用 `启动-鞭尸模式.cmd`（会等 300 秒），或加 `--wait 300` |
| `Client version mismatch` | 游戏版本和本补丁记录的 exe 哈希不一致 | 换对应版本的补丁；或按 `docs/02` 第 7 节重新测偏移 |
| `Refusing a process outside the isolated client` | 同名的其它进程被选中 | 用 `--pid` 指定真正的 `sf2.exe`（`runtime\test-client\Binaries\Win32\sf2.exe`） |
| `无法安装桥：Expected original Actor ProcessEvent entry` | 入口字节既不是原始指令也不是跳转：已被别的补丁改过，或版本不同 | 关掉其它补丁；或确认游戏版本与 `docs/02` 的 `HOOK`/`EXPECTED` 一致 |
| `桥命令块状态异常` | 桥是旧进程留下的，命令块已失效 | 重启游戏（跳转会恢复到原字节），再启动补丁 |
| `游戏主线程没有响应（status=...）` | 游戏被最小化/暂停，主线程不推进 | 让游戏窗口在前台可见；不要用 `--dry` 跑在后台被挂起的游戏 |
| `游戏拒绝了这条调用（native batch rejected）` | 参数打包不匹配（结构体大小/对齐） | 对照 `docs/02` 第 4 节的 36 字节帧，检查 `struct.pack` 格式 |

> 桥安装失败时**不会**留下半截补丁：`install()` 只有在入口字节完全匹配时才写内存；
> 失败会抛异常并退出，游戏继续正常运行。

## 2. 运行阶段

| 现象 | 检查 | 原因 / 处理 |
| --- | --- | --- |
| 日志里 `ready` 之后没有任何 `shot-miss` / `corpse-hit` | `weapon` 事件出现了吗 | 没进对局 / 手里没枪时不会开火；进一局再试 |
| 每发都是 `shot-miss` | 看 `impacts[].actor` | ① 打的是墙/地面（正常）；② 武器不是 `SFWeap_Bullet`（刀、弓、投掷物另走一套，见 `docs/03` 3.4）；③ 用的是载具/炮塔武器 |
| `corpse-hit` 出现但尸体不动 | 看 `settled.moved` | `moved` ≈ 0 ⇒ 冲量太小（静摩擦门槛约 600），把 `--strength` 调到 800~1200 |
| 尸体被推得太远 | `settled.moved` > 50 cm | 调低 `--strength`（默认 700 对应 5~20 cm） |
| 打空也推了尸体 | 日志里 `impacts` 是否包含尸体 actor | 若包含，说明子弹**真的**穿到了尸体（穿透弹），属于真实命中；若 `impacts` 没有尸体却推了，请把日志整段保留并提 issue（说明命中表被复用/去重失效） |
| 只有爆头才动 | — | 这是旧版本的几何判定行为；本版本任何部位都有效。若仍复现，确认跑的是 `corpse_flinch.py` 而不是旧的 `flinch.py` |
| 换图后不再响应 | 日志里有没有新的 `world` 事件 | 有 `world` 事件但 `tracked=0` ⇒ pawn 表读取失败，跑 `selftest.py` 看世界/关卡指针 |
| 开枪后游戏明显卡顿 | 日志时间戳 | ① `poll_seconds` 太小（默认 0.004）；② 自己在 `shot()` 里加了 `GetBoneName` 之类的重调用（单次 ~20 ms） |
| 补丁在，但游戏崩了 | `docs/02` 的桥说明 | 只在游戏主线程推进时调用；不要并发多线程调 `invoke`。崩了重启游戏即可，游戏文件未被修改 |
| 控制台中文乱码 | — | 先 `chcp 65001`；日志文件本身是 UTF-8，用支持 UTF-8 的编辑器看 |
| 按 E 没反应（拖不动） | 日志里有没有 `drag-none` | 有 ⇒ 3 米内没有尸体（`near` 是最近骨骼距离，比 `reach` 大就是超距了）；没有 ⇒ 按键没被识别，跑 `selftest.py` 看 `bPressingUsedKey`，或把 `drag_key` 设成别的键 |
| 抓到了但拖不走 | `drag-start` 后的 `drag-end.reason` | `too-far` 600 cm 太远（尸体卡墙里了，走近再按）；`mesh-lost` 尸体被清理/换局；`invoke-failed` 桥断了（看游戏是否最小化/暂停） |
| 拖起来乱甩、抽搐 | `drag-end.calls` 与 `path` | 先看 `drag_hz`：如果它被调高到 120 以上就会开始抖（冲量喂得比物理积分还快）。仍抖就加大 `drag_kd`（9 → 14）、把 `drag_impulse` 降到 600~800 |
| 打字/切窗口时尸体被拽 | — | 说明退回了 `GetAsyncKeyState`（`selftest.py` 里 `bPressingUsedKey` 读不到）；先修偏移，或临时 `"drag": false` |
| 按 E 之后尸体翻着跟头飞走、几秒就松手 | `drag-start` / `drag-end` 里的 `bone_name` 是不是手/头 | 1.9.2 起抓的是骨盆；若不是，说明没找到 `Bip01-Pelvis`（换了骨架或名字），`center_index` 会退回准星那根骨，请把 `bone` 名字发我 |
| 抬头看天，尸体贴在地上不动 | `drag-end` 有没有立刻 `too-far` | 那是 1.9.0 的行为（目标点是压平的朝向）。1.9.1 起目标点跟着相机走，若还不动就把 `drag_max_speed` 提到 1000 |
| 按 E 捡枪却把尸体拽了 | 正常 | 交互键同时触发两件事；把 `drag_reach` 调小到 150，或先捡枪再拖 |
| 投掷武器（飞斧/投掷刀）打尸体没反应，日志里没有 `projectile-hit` | 投掷物没有在尸体 70 cm 内被销毁：打空、打墙、落在空地都不会算命中；1.8.1 及更早版本的阈值是 45 cm，会把正常距离的真实命中（实测 60.9~63.9 cm）全判成 miss | 先看 `logs\*.jsonl` 有没有 `projectile-spawn`（说明补丁看见这把投掷物了）；只有 `shot-miss` 且 `impacts: no-bullet-trace` 是正常的（手里不是子弹类武器）。务必用 1.8.2+ |
| 投掷武器的左键近战推不动尸体 | 这个动作只有 `BurstFireCount` 可用，补丁要等 0.3 s 看弹药有没有减少才敢判 | 用 1.8.2+；看日志有没有 `{"event":"swing","source":"weapon-swing"}` |
| 投掷/挥击打中了，尸体隔半秒才动 | 1.8.1 及更早版本用"起飞后 0.12 s 内的采样不算"来挡"站在尸体上投掷"的误判，近距离投掷的整个接触段都被吞掉，冲量要等投掷物落地停稳才施加 | 用 1.8.3+；日志里 `projectile-hit` 的 `age` 应在 0.05 以内 |
| 开一枪尸体被推了两次 | `BurstFireCount` 同时被"开枪"与"挥击"置位，只靠弹药区分 | 确认 `ammo_drop_at` 正常（`status` 里 `ammo` 在变化）；0.45 s 去重只在一次动作内生效 |

{"event":"world","world":"0x62a10380","tracked":4,"corpses":1}

- `moved` 是 0.35 秒后 mesh 世界坐标的位移，包含被地形挡住的情况；

- 结束时 `{"event":"stopped","shots":N,"hits":M}`。

## 4. 彻底重置

1. 关掉游戏（1.10.3 起 worker 会写 `{"event":"game-exit"}` 自己退出；旧版要先按 `logs\worker.pid` 停 worker，见 `docs\05` §4.5）；
2. 删 `<游戏>\mods\corpse-flinch\logs\`（可选）；
3. 需要重装就删整个 `<游戏>\mods\corpse-flinch\` 再跑 `安装.cmd`（删不掉多半是被 Obsidian/编辑器占着，见 §0 最后一行）。

游戏本体、存档、配置、`runtime\` 都不会被本补丁改动，无需备份还原。
