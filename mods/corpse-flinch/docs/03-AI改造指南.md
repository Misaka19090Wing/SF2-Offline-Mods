# 03 · 改造指南（给 AI / 开发者）

这份文档的目标：**你拿到这个包，不改游戏文件，也能安全地加功能。**
先读 `docs/01-原理.md` 知道数据从哪来，再读 `docs/02` 拿偏移，然后回到这里挑一个改法。

## 1. 硬性约定

1. `sf2mod\` 里不写业务策略，业务在 `corpse_flinch.py` 的 `Worker` 里；新增效果请加新模块，别把几何/判定逻辑塞回 `signals.py`。
2. 每次改完跑 `tools\selftest.py`（只读）+ `corpse_flinch.py --dry`（看判定，不推）。
3. 日志一律 `emit(event=..., ...)` 单行 JSON，字段名用小写、坐标保留 1 位小数——别人的 AI 才能稳定解析。
4. 不要修改游戏文件、不要写注册表、不要在游戏进程外读文件之外的任何持久状态。
5. 不要每发子弹扫描 `GObjects`（18 万对象，5.2 秒）；一切走 `UWorld → PersistentLevel → Actors`。
6. 桥的 `invoke` 必须在游戏主线程推进时才能完成；游戏最小化/暂停会超时（`TimeoutError`）。批量施加冲量时合并调用，单发只调一次。
7. **`.cmd` 文件里不许出现非 ASCII 字符。** cmd.exe 用系统 OEM 代码页解析批处理，中文写在批处理里会变成一堆"不是内部或外部命令"。中文提示放 Python（`tools\install.py` 等），批处理只当薄壳，路径用 `%~dp0`。
8. 改完任何文件都要跑 `tools\build_manifest.py --zip <名字>.zip` 重新生成清单，否则别人 `--check` 会报"被改"。文档里提到的偏移、路径、函数名必须和代码一致——这是别人 AI 敢改的前提。

## 2. 模块地图

```

  └ sf2mod.attach     game_dir / find_pid / load_runtime / Bridge(桥) / connect
  └ sf2mod.game       偏移常量、Pawns、Player、matrix_translation、bone_world、is_skeletal_mesh
  └ sf2mod.signals    read(bridge, weapon) -> [ {list, actor, loc, normal, dir, start} ]
  └ sf2mod.punch      Punch.apply(mesh, loc, dir, scale) / Punch.settle()
  └ sf2mod.swing      Swing.poll(pawn, weapon) -> ['exigency'] / ['burst']
  └ sf2mod.projectiles Projectiles.sample() -> 折线；Worker.path_hit() 做线段判定

```

安装/启动路线（和上面的运行期模块是两回事，改安装流程才需要动它们）：

一次开火的完整调用栈（`Worker.shot`）：

```
impacts = signals.read(bridge, weapon)          # 游戏自己的命中表
for entry in impacts:
    if entry.list == 'penetration': continue    # 穿出点不是新命中
    if not pawns.is_corpse(entry.actor): continue
    mesh = u32(actor + game.MESH)
    punch.apply(mesh, entry.loc, entry.dir)     # -> AddImpulse
```

**想加功能，九成落在 `shot()` 里"已确认是尸体"之后的这几行。**

## 3. 常见改造

### 3.1 按部位区分力度（头重、四肢轻）

命中表不给骨骼名，但可以在命中点附近找最近的骨骼：

```python
FIND_CLOSEST = 'Engine.SkeletalMeshComponent.FindClosestBone'
GET_NAME = 'Engine.SkeletalMeshComponent.GetBoneName'

def bone_at(bridge, api, mesh, point):
    fn = api.functions[FIND_CLOSEST]                    # (Location, BoneName, ReturnValue)
    frame = struct.pack('<3fQQ', *point, 0, 0)          # FVector + 2 个 FName 槽位
    raw = bridge.invoke(mesh, fn, frame, timeout=1.0)
    index = struct.unpack_from('<Q', raw, 12)[0]        # ReturnValue: FName (index, number)
    name_fn = api.functions[GET_NAME]                   # (BoneName, ReturnValue)
    out = bridge.invoke(mesh, name_fn, struct.pack('<QQ', index, 0), timeout=1.0)
    return out[16:].decode('latin1').split('\0')[0]      # FString 正文
```

拿到名字后按 `head / spine / hand / foot` 给不同 `scale`，传给 `punch.apply(..., scale=...)`。
默认 `scale=1.0`，`punch.magnitude()` 会做 `min(strength*scale, max_impulse)`。

> 注意：`GetBoneName` 一次约 20ms，`FindClosestBone` 类似。**不要在连发时对每一发都调**；
> 可以先缓存"每具尸体最近的几根骨"或只对需要区分的情况调用。

### 3.2 只对爆头生效

最稳的做法是用游戏自己的爆头判定而不是骨骼距离：`SFWeap_Bullet.HeadShotSuccess` /
`ProcessInstantHitSub` 的参数里就有 `nHitType / bodyParts`。若不想解这些参数，退一步：

```python
head = bone_at(...)                      # 3.1
if 'head' not in head.casefold():
    return                               # 不推
```

### 3.3 让冲量随距离衰减

命中表里 `loc` 与 `start` 都有，直接算：

```python
distance = math.dist(entry['loc'], entry['start'])
scale = max(0.35, 1.0 - distance / 6000.0)
punch.apply(mesh, entry['loc'], entry['dir'], scale=scale)
```

### 3.4 弓 / 投掷刀（投射物武器）—— 已实现，见 `sf2mod/projectiles.py`

枪走 `SFWeap_Bullet.HitResult`，但弓和刀**没有这份记录**（`HitResult` 只声明在
`SFWeap_Bullet` 上）。它们真正的可观测物是**投射物 actor 本身**：客户端会在关卡里生成
`SFCProjectileBowArrow` 之类的蓝图对象并逐帧移动它。

`projectiles.py` 的做法：

1. 每轮遍历关卡 actor 表，筛类名以 `SFCProjectile` 或 `SFProj_` 开头者；
2. 记录每个投射物的采样折线（最多 64 点）与 `Velocity`；
3. actor 消失时交出一条 `gone` 事件。

判命中的关键事实（实测，1.3.0 修正）：**打中身体的投射物会在接触瞬间被销毁**，而落在
地面的那一把会保留模型、对象继续存在 —— 对着尸体投的飞斧 **0.87~0.89 s** 就没了，落在空地上
的那把活了 **16.9 s**。

所以判定只看**销毁前的最后 4 个采样点**：这些点与尸体骨骼的最近距离不超过
`projectile_radius`（默认 **70 cm**）才算命中，吃力点取最近点，方向取投射物最后的速度。
末速度可能是朝下的（弧线投掷），一律过 `Worker.slide()` 压平 + 0.08 抬升。

70 cm 这个数是三种实测情况夹出来的：贴脸直击 1.9~12.9 cm；站远一点对准尸体投 **60.9~63.9 cm**；
对着空地投 1500 cm 以上。用 45 cm 时第二类会全部漏判（1.8.1 实测三次全 miss）。别为了"更准"
把它调小 —— 那只会让真实命中消失，打空地被判成命中的风险在 1500 cm 这个量级上根本不存在。

**起飞阶段的两个过滤器不能混。** 1.8.1 只用时间宽限（0.12 s）挡"站在尸体上投掷"，可 0.12 s
按 24 m/s 算是近 3 米飞行，近距离投掷的接触段全在窗口里 → 冲量推迟到投掷物落地（约 0.8 s），
玩家体感就是"投掷延迟很高"。正确拆法是：

1. `projectile_grace`（0.02 s）：只丢"还在手里"的那一个采样；
2. `projectile_launch`（0.15 s）内的采样，额外要求 `(骨骼 − 出手点) · 线段方向 > 0`：脚下的尸体
   在正下方（点积≈0）被排除，正前方 60 cm 的尸体（点积≈+60）正常算命中。

改这两个值时，务必在日志里对比 `projectile-hit` 的 `age` 字段：修好后应该 ≤ 0.05。

> ⚠️ 不要用**整条折线**判命中。飞斧是穿透的：直击时整条折线的最近点是 1.9~12.9 cm，
> 但擦身而过也有 33~39 cm，而两者都会在约 1 秒后掉出地图被销毁。只有"在尸体旁边销毁"
> 这个时机 + 销毁点位置合起来，才是游戏自己的裁决。1.2.0 就是用"存活时间 < 3 s + 整条折线
> ≤ 14 cm"判的，结果正常距离的真实命中（末帧 20~30 cm）全被漏掉 —— 这就是"投掷武器没反应"
> 的直接原因。
>
> 另一个坑：对象释放后仍会在关卡 actor 表里留一帧，位置读出来是垃圾（z≈9970）。
> `projectiles.poll()` 用"单帧位移 > 400 单位"丢掉这种采样，否则死亡点会被污染。

施加冲量前会过一遍 `Worker.slide()`：尸体都躺在地上，直接按投射物速度方向（常是朝下）推，
只会把它压进地板（实测 `settled.moved` 只有 2~8 cm）；`slide()` 只保留水平朝向 + 0.08 的抬升。

要扩展到别的投射物（飞刀、飞斧、投掷锤）：确认它的类名以 `SFCProjectile` 或 `SFProj_` 开头
（`game.PROJECTILE_PREFIXES`），一般不用改代码。新增类名前缀时改这一处即可。

### 3.5 近战 —— 已实现，见 `sf2mod/swing.py`

近战同样没有持久命中记录：`SFWeap_Melee` 的 `DamagedActors`/`ImpactList` 只是函数**参数**，
伤害由原生代码直接结算。可用的信号有两个：

- `SFPawn_Player.DoingExigencyAttack`：BoolProperty，偏移 `0xED8`，掩码 `0x8`，**F 键挥刀**期间为 1；
- `SFWeapon.BurstFireCount`：IntProperty，偏移 `0xBE0`，动作开始 0 → -1，结束回 0。开枪、投掷、
  **投掷武器的左键近战**都置这个位。

`swing.py` 每次轮询读这两个位置，分别给出 `['exigency']` 与 `['burst']` 两种触发；然后
`Worker.melee()` 用相机位置找最近的尸体骨骼，距离不超过 `melee_reach`（默认 130 cm）就在那根
骨头上施加冲量。为什么要用骨骼而不是 actor 原点：实测站在尸体上挥刀时，尸体 actor 原点
可能在视线**背后**（`cosine = -0.08`、`along = -0.9`），只有骨骼坐标能正确表达"砍到了"。

`burst` 这一路必须再区分一次，否则每开一枪都会多推一次：

1. 记下触发时刻的 `ammo_drop_at`（上一次弹药减少的时间）；
2. 等 `swing_delay`（默认 0.3 s），若弹药在这期间减少了 ⇒ 是开枪/投掷，丢弃；
3. 否则当成挥击（挥砍不减弹药），用**触发时刻**的相机位姿去判距离。

实测依据：飞斧左键近战三次脉冲各约 0.79 s、弹药不变；同一把飞斧投掷是脉冲 + 弹药 1→0；
M4 射击是脉冲 + 30→29、脉冲只有 0.09 s。

想改成"只砍到头才生效"，把 `nearest_bone` 换成正前方射线、并要求命中骨的编号落在
`Bip01-Head` 那一支上（骨骼编号与名字可用 `Engine.SkeletalMeshComponent.GetBoneName` 现查）。

### 3.6 连发时合并冲量

`invoke` 一次约 20ms，连发（600 RPM ≈ 100ms/发）勉强够用，但不要一发里调多次。
若要"三连发累积一次大推力"，把 `pending` 改成按 actor 累积，在 `settle()` 里一次性施加：

```python
item['amount'] += amount
...
punch.apply(mesh, item['loc'], item['dir'], scale=item['amount'] / self.strength)
```

### 3.7 加新事件 / 新日志字段

```python
self.emit(event='corpse-push', corpse=name, bone=bone, moved=moved)
```

字段保持小而平，别嵌套超过一层——文档与别人的脚本都按顶层字段解析。

### 3.8 拖拽（E 键）—— 已实现，见 `sf2mod/drag.py` + `sf2mod/keys.py`

要点只有三条，改动时别破坏它们：

1. **不能直接改速度**。`Engine.PrimitiveComponent.AddImpulse` 有 `bVelChange` 参数，但本版本是空操作（见 `punch.py` 的注释），`AddForce` 连 `bAccelChange` 都没有。所以拖拽是"每 tick 一次普通冲量"的速度伺服，**临界阻尼 PD**：
   `accel = drag_kp × 误差 − drag_kd × 速度`，`impulse = drag_mass × (accel × dt)`（`kd ≈ 2√kp`）。
   三条别破坏：① 控制频率 `drag_hz = 60`，**不要**在每个 4 ms 轮询里发冲量（1.9.0 就是这么鬼畜的）；
   ② 重力补偿 `+980 × drag_gravity` 必须加在限速**之后**，否则会被 `drag_max_speed` 削掉、尸体会下沉；
   ③ 速度差分要低通（现在 0.5/0.5），否则噪声进阻尼项就是可见抖动。
   ④ 冲量必须打在**骨盆**（`Drag.center_index` 按名字找 `Bip01-Pelvis` 并缓存），不能打准星最近的那根骨：
   头/手离质心远，冲量几乎全变成力矩，实测抓头会把尸体甩出 7 m。
2. **每 tick 现读骨骼**。`game.bone_world(mesh, index)` 只读一根骨的矩阵平移（`pointer + 32*index + 16`），不要用 actor 位置——布娃娃的根和"你抓的那只手"差着半米，用 actor 位置会出现"抓到手却拽着脚走"。
3. **按键读游戏状态位**。`SFPlayerController.bPressingUsedKey`（0x690，掩码 0x40）是游戏自己的交互键状态，跟着改键走、聊天框里不置位；只有它一直读不到（比如换了版本偏移变了）才退回 `GetAsyncKeyState`，并且一旦 `native_ok` 就别再用 OS 边沿，否则打字也会触发。

新增行为要发 `drag-start` / `drag-none` / `drag-end` 三种事件，`drag-end` 必须带 `reason`（`toggled` / `too-far` / `world` / `mesh-lost` / `invoke-failed` / `no-player`），否则日志里分不清"用户松手"和"尸体丢了"。

想改成"抓最近的一整块"（而不是单根骨头），可以把 `grab` 的 index 换成躯干骨（`Bip01-Spine*`），其余不变——伺服逻辑与骨头无关。

## 4. 调试配方

| 目的 | 做法 |
| --- | --- |
| 确认判定对不对 | `corpse_flinch.py --dry`，日志里 `corpse-hit-dry` 应只在真打中尸体时出现 |
| 确认力度 | `--strength 700`，看 `settled.moved`，正常 5~20 cm |
| 确认没有误伤活人 | 代码只在 `Health<=0` 时施加；`corpse-hit` 的 `corpses[]` 只应出现已死亡 pawn，活人命中只会是 `shot-miss` |
| 复现"卡住" | `TimeoutError` = 游戏没在渲染（最小化/暂停）；`status>4` = 桥命令块损坏，重启游戏 |
| 只用一具尸体做标定 | 用 `--seconds` 限时，配合日志里 `settled` 的 `moved` |

## 5. 陷阱清单

- **不要缓存 actor 类名太久**：actor 槽位会被回收，`Pawns` 每 100 次 poll 清一次缓存；自己写的新缓存也要有失效策略。
- **换图必须清状态**：`Worker.run()` 里 `pawns.world` 变化时会清 weapon/ammo/签名/去重表。新模块同样要挂在这里。
- **弹匣递减可能连跳**（换弹、作弊、拾取）：只有 `ammo == previous - 1` 才算一发；换弹从 0→30 会被忽略。
- **命中表被复用**：同一发子弹的 `ImpactInfos` 在下一发之前不会变；用签名去重，否则会重复施加。
- **`penetration` 条目**是穿出点，不是新命中，必须跳过。
- **游戏进程重启后**：桥失效（跳转字节还在但命令块属于旧进程），脚本里的 `Bridge.state()` 会重新探测；最简单是重启补丁。
- **反作弊/杀软**：本补丁会 `OpenProcess`、`VirtualAllocEx`、改 9 字节代码，可能触发误报；文档里已声明行为，分发时建议附上源码与 `MANIFEST.sha256`。

## 8. 与 AI 代理协作

这个仓库是**给 AI 接手设计**的：

- [`AGENTS.md`](../AGENTS.md) 是契约（不变量、环境事实、陷阱、定义完成），任何代理开工前必须读
- [`06-日志字段.md`](06-日志字段.md) 是机器可解析的"证据层"：一次改动是否生效，用日志说话，不靠肉眼判断
